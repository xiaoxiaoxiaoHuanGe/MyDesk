# CPE 短信与文本通知接入

本次实现 MyDesk 接收端。发送方分别向原飞书地址和 MyDesk 地址投递，各自记录成功；MyDesk 不保存飞书地址、不转发消息、不连接或修改真实 CPE/电脑代理配置，也不执行短信中的命令。旧 `/api/webhook/{secret}` 任务结果协议不变。

设置 → 通知接入支持创建 CPE 或通用文本来源、重命名、启停、重置密钥和确认删除。创建/重置只返回一次接收地址，立即复制；数据库仅存 SHA-256 密钥摘要。密钥为 32 字节安全随机数。删除为软删除，历史来源名和正文保留。重置立即使旧地址失效。

管理和收件箱接口需要会话，写入需要既有 CSRF。只有严格匹配的外部 POST 接收路由豁免会话，并用来源密钥鉴权。APP 用当前已校验 HTTPS 服务器地址拼接；Web 用当前同源地址拼接；后端只返回相对路径，不从不可信 Host/转发头生成地址。

## 发送契约

```sh
curl --fail-with-body 'https://mydesk.example/api/incoming/feishu/aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa/bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb' \
  -H 'Content-Type: application/json; charset=utf-8' \
  -H 'Idempotency-Key: 0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef' \
  --data-binary '{"msg_type":"text","content":{"text":"📱 短信通知\n发送方: CPE 测试发送方\n内容: 【示例】验证码 123456，这是测试短信。\n时间: 2026-10-07 20:00:00 +08:00"}}'
```

以上是占位 URL 与假密钥，不能实际用于生产。来源类型 CPE 必须带 64 位小写十六进制 `Idempotency-Key`，不用另加 Bearer 或正文 event_id。通用文本可省略 ID，此时每次请求独立保存；提供 ID 时也执行同来源幂等。不同来源可用相同 ID。

UTF-8 正文、中文、emoji、引号、换行、正文时间完整保存，不 trim、不解析号码/验证码。服务器另存 UTC 接收时间；正文北京时间 +08:00 不改写。仅支持 `msg_type=text` 与 `content.text`，额外飞书 `timestamp`、`sign` 可接受但不作 MyDesk 鉴权。富文本、卡片、图片、附件及未知结构明确返回 400。消息显示为文本，不加载 HTML/WebView。

成功在 SQLite 事务提交消息和派发待办后，直接返回：

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"code":0,"msg":"success"}
```

同来源同 ID 重试返回完全相同成功响应，不更新原文，不重复创建消息或派发待办，即使正文发生变化也保留第一条。使用数据库唯一约束和事务保证并发幂等。格式 400、密钥 401、停用 403、不存在/删除 404、超限 413、来源限流 429（Retry-After: 60）、临时存储失败 500，返回非零数字 code 和 msg，不重定向到登录页。

请求上限为整个 UTF-8 JSON 64 KiB，每来源最多每分钟 60 条新接收（幂等成功重试不新计入消息额度）。正文不因推送限制截断；系统通知标题最多 120 个 UTF-16 单元，摘要最多 500 个 UTF-16 单元，避免 emoji 触发旧协议长度拒绝。推送 event_id 仍为 32 位内部 UUID 十六进制，CPE 64 位 ID 独立保存。

按收到时间保留 90 天，或最近 10000 条（先达到限制者），关联派发/通知记录一并清理，来源不清理。幂等保证覆盖仍保留的消息；超过保留期/总量淘汰后重试可再次接收。不要按号码与正文再次去重。

## 收件箱、同步与通知

APP 四个底部导航不变，最近邮件后增加最近通知，最多三条。设置保留通知入口，全部列表有分页、来源筛选、详情、单条和全部已读。全部已读以当前列表最新序号为截止，不将新到消息误读。前台 WebSocket 只同步最近三条摘要、来源和未读数，完整正文从鉴权分页/详情接口获取。Web 设置中同样提供管理与收件箱，工作台提供最近通知。

APP SQLite 新增兼容迁移的 `inbox_cache`、`inbox_read` 表，加载过的消息可离线查看，未加载的正文不能凭摘要恢复；已读操作先进入本机持久队列，联网通过原同步链路重试，服务端幂等。注销/切换服务器清理消息缓存和已读队列，过期账户结果不能写入新缓存。

入库成功不等待 FCM。持久派发待办通过后台处理生成原有原生事件/设备投递，事务处理确保重启和突发到达不受最近三条窗口限制。复用设备绑定、会话、registration_id、去重、重试与一小时有效期；过期短信只同步收件箱，不重新弹锁屏通知。新渠道“外部通知”；旧客户端白名单会安全忽略新类型。点击通知定位消息，已清理消息显示提示并留在收件箱。普通通知不进入需要处理、任务、步数记录。

没有 Firebase 后端凭据时，设置显示“消息可同步，后台推送未配置”；已有手机 Google 服务不代表个人 Firebase 绑定完成。入库、FCM 提交、手机接收、系统显示是不同事实。

## CPE 本地接续

1. 由维护者部署后端和 HTTPS，验证证书可被 CPE 系统 CA 信任，接口不跳转。
2. 创建“CPE 短信”来源，复制完整地址到 CPE 第二目标的 url；路径密钥方式 headers 可为空，发送器仍需按约定发送 Idempotency-Key。
3. 实际启用时填写当前 UTC `enabled_at`，不要复用文档示例时间。按计划转述的发送方规则：首次启用跳过更早历史，同 URL 暂停再启用沿用状态，改变 URL 重建基线。重置密钥会改变 URL，须核对切换期间短信与启用时间，避免漏接。
4. 电脑代理白名单只加入 MyDesk 域名/HTTPS 端口，不保存带密钥完整 URL；原协议说明已有代理程序需重启一次加载新版代码，之后白名单文件动态读取；正式接续时核实当前程序状态。此处不宣称第二目标已在真实 CPE 部署。
5. 原飞书通道与 MyDesk 独立处理成功；MyDesk 故障不得更改飞书成功记录。发送端协议检查周期 180 秒、超时上限 20 秒；正式接续仍应核实实际配置。
6. 联调新短信双端收到、MyDesk 临时不可达而飞书成功、恢复后补发、事务成功但 ACK 丢失后幂等重试、服务器重启、手机离线补同步以及后台通知点击。

[CPE 发送方协议原文](CPE_WEBHOOK_PROTOCOL_REFERENCE.md)已按上传内容原样保存。自动化测试直接读取其中完整 JSON 样本，验证原文保留、严格成功应答及丢失 ACK 后重试幂等。协议中的手机和发送端状态仅为原文陈述，本次未做真实设备核验。

## 反向代理日志

服务端启动器已禁用 aiohttp 访问日志，业务诊断只记录通用失败，绝不打印短信、验证码或密钥。代理也必须针对接收路由禁用访问日志，并处理错误日志中附带的原始请求 URI。示例按现有可信代理配置合并，保留 HTTPS 和既有反代边界：

```nginx
location ~ ^/api/incoming/feishu/[a-f0-9]{32}/[a-f0-9]{64}$ {
    access_log off;
    error_log /dev/null crit;
    proxy_pass http://127.0.0.1:8787;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 64k;
}
```

代理层限流可额外保护匿名异常请求；后端不相信请求自报 IP。应用层才能返回 CPE JSON 格式错误，代理拒绝的请求可能只有非 200 响应，但发送方仍应保留并重试。不要把完整接收地址放进普通诊断工单或日志。
