# 渐进步数与需要处理入口

服务端计划从 1.1.0 起提供；1.2.0 增加 APP 独立“步数”页面、统一保存配置与异常确认。网页和 APP 使用相同的服务端计划。新版 APP 操作详见 [1.2.0 更新说明](ANDROID_1_2_0.md)。

## 如何开始

保留原来的手动提交。在 APP 底部打开“步数 → 自动任务”（网页入口为“管理渐进任务”），输入起始步数、每次增加、间隔分钟和终止步数，确认预览后点“立即开始”。起始步数由自己填写，无自动推测。新版 APP 选择快捷配置会填入步数参数和该配置的每日安排，不开始任务、不保存或启用每日计划；网页旧入口仍只填入四项数字。

例如起始 1000、每次增加 30、间隔 3 分钟、终止 1090，提交为：1000 → 1030 → 1060 → 1090 → 1120。等于终止步数继续，第一次超过的那次也实际提交，确认成功后完成。受原有工作流限制，输入和最后一次提交均不超过 30000；允许起始为 0，间隔为 1–1440 分钟。

## 状态和终止

显示当前提交、最近成功值、成功次数、下一次提交与倒计时。每轮记录逐页查询，可查看每次时间、数值、来源、成功或失败结果。

“终止本轮”立即停止后续提交；已经发出的 GitHub Actions 无法撤回，仍跟踪其结果。“关闭每日计划”同时关闭未来每日启动和终止本轮。停止操作在提交过程中仍可用。

明确失败后暂停，检查原因后恢复会重试同一数值。结果不确定时不重复发送，需要先查看 GitHub Actions；可使用原有“检查后结束本地跟踪”，随后决定重试或终止。工作流更换后旧轮次暂停，需要重新开始。

全局同一时间只有一笔步数提交。手动提交只在渐进任务等待期间允许；成功后从手动值继续增加，手动值超过目标则完成本轮。不能提交低于本工作台当天已确认成功的值；工作台无法读取第三方直接修改后的当前微信步数。

## 预设和每日重复

预设支持新增、更新、另存、删除、前移和后移。保存预设不提交步数，修改或删除预设不影响已开始轮次；最多 50 个，名称必须不同。

新版 APP “保存配置”同时保存快捷配置、四项参数、每日开关和开始时间，不立即提交步数。网页“保存设置”继续只保存计划设置。每日设置次日生效，按工作台时区每天最多自动启动一轮。跨日时停止昨日未完成的每日轮次；离线期间不补发积压提交。请保持后端运行，关闭 APP 不影响计划。默认每日重复关闭。

计划、预设和记录持久化在 data/mydesk.sqlite3，终止和暂停状态重启后保留。历史保留天数沿用工作台设置；未完成轮次的记录保留。现有“配置备份”针对服务接入配置，迁移这些计划数据时请备份完整 data 目录和 SQLite 数据库。

## 需要处理

点击前查询最新状态，已处理或已移除的事项不会误操作旧记录。提醒打开完成、取消、稍后提醒入口；自动任务打开详情和记录；服务器打开详情或对应接入配置；网络异常打开对应节点并可重新检测；邮件等接入错误直接打开相关配置；步数异常打开任务记录处理入口；新版 APP 可点击“已知晓”确认本次事项，保留记录，新的失败继续提示。

## 验证

初版 1.1.0 通过后端 165 项、Android 109 项、前端 14 项测试；隔离浏览器验证预设填入、增删排序、连续保存、320/400/1440 宽度、严格超过序列、结果记录和运行中终止。验证使用模拟工作流，不提交真实微信步数。

## 1.3.0 随机浮动

新建配置默认 ±10%，旧预设、设置和进行中的轮次缺少 `random_percent` 时为固定模式；编辑后可显式保存 0 或 10。每轮保存参数快照。基准 I 的浮动为 floor(I × 10%)，从闭区间 `[max(1,I-浮动), I+浮动]` 均匀抽取整数，允许重复。例如 80 → 72～88；I=1 时实际仍为 1。

首次提交保持起始值。只有确认成功且未严格超过终止值时才抽取下一增量，在同一事务保存成功确认和下一具体步数。网络失败、重复成功回调、重启与失败恢复不会改变已确定值；仍串行提交。随机末次封顶 30000，可小于下限；终止值必须小于 30000。固定模式沿用首次越过仍不超过 30000 的校验。

设 D=终止-起始，L/H 为增量上下限：预计总提交次数为 `[floor(D/H)+2, floor(D/L)+2]`，间隔估算耗时为 `[floor(D/H)+1, floor(D/L)+1] × 间隔`，最后值范围 `[终止+1,min(终止+H,30000)]`。每日跨日校验使用最慢上界；排队和失败重试会额外增加耗时。运行时“下一次”继续显示后端已保存的精确值。

新 APP 和 Web 使用显式后端能力标志。旧服务器缺少随机能力时禁用新操作并提示升级，避免界面说随机而服务端按固定执行。预设往返、历史详情与新随机字段一起保留；Web 切换预设仍不误改每日时间。
